Agent roles flow

Claude owns analysis, design, the UI build and integration; Codex starts building the server, data and logic first and reviews every branch as it finishes. You confirm requirements, make significant decisions and decide serious review findings. The diagram below shows who does each step and where the work comes back to you.

Rules the diagram doesn't show

Three sizes

Small work: one agent, straight to build. Medium: one plan file with requirement IDs, contract and tasks, approved once. Large: every step and gate.

Codex starts first

After planning, Claude starts the Codex tasks, then builds the UI and reads worker reports as they arrive, so no worker waits.

Contract stub first

When work spans UI and server, the first task is the shared types plus a mock of the API. The UI and the server are then built at the same time.

Review each branch as it finishes

Approved branches merge without waiting for the others. Large work also gets one review of the whole merged diff. The author never gives the final review.

Two review rounds, then Claude decides

Round 2 checks only the fixes; Claude does it when they're small, a fresh reviewer when they're serious. No third round: Claude fixes, accepts, defers or drops each open finding.

What the sandbox can't run

Hand-offs list checks the sandbox blocks, such as browser tests on local ports. Claude runs them, plus the rendered, keyboard and accessibility checks of the UI.

Workers keep Personal Brain

Never enabled=false or --disable hooks. If a worker can't reach Personal Brain, Claude stops and asks you.

Blocked: one retry

A blocked or timed-out worker gets Claude's decision and one restart. If it's blocked again, Claude takes the task over.

Requirement changes go back

A new or changed requirement goes back through analysis, design and planning, and built work is re-checked against it.
